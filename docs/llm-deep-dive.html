The one idea that unlocks this whole file:
Every function in llm.py does the same thing — it builds two strings (a system prompt and a user prompt), sends them to Claude, and returns what Claude writes back. The only thing that changes between functions is what those strings say.

llm.py — lines 16–24
def call_claude(system_prompt, user_prompt, max_tokens=4096):
    response = client.messages.create(
        model=MODEL,
        max_tokens=max_tokens,
        system=system_prompt,
        messages=[{"role": "user", "content": user_prompt}],
    )
    return response.content[0].text
max_tokens=4096 Default value in the function signature If you call call_claude(s, u) without a third argument, max_tokens is automatically 4096. If you call call_claude(s, u, max_tokens=8192) it uses 8192. This is Python's default parameter syntax.
client.messages.create(...) The actual API call This sends an HTTPS request to Anthropic's servers. The code pauses here and waits for Claude to respond — this can take 5–30 seconds depending on how much Claude needs to write.
system=system_prompt Who Claude is for this call The system prompt is passed as a separate field — not as part of the messages list. This is intentional: Claude treats the system prompt as a persistent identity that's harder to override.
messages=[{"role": "user", "content": user_prompt}] The conversation history This is a list because Claude's API supports multi-turn conversations (user → assistant → user → ...). Here we always have just one message: the user's request. The list wrapping is required by the API even when there's only one message.
response.content[0].text Extracting Claude's text from the response object response is a Python object with many fields. response.content is a list of "content blocks" — Claude can return text blocks and tool-use blocks mixed together. [0] takes the first one. .text extracts the string. We always get exactly one text block here.
⚠️
max_tokens is the OUTPUT limit only. Your input (the prompts you send) has a separate limit of 200,000 tokens and is counted separately. max_tokens only controls how long Claude's response can be. If Claude's answer would naturally be longer, it gets cut off mid-sentence.

First call in the pipeline. Takes a wall of raw scraped website text and asks Claude to pull out only the useful structured data.
inscraped_text: str (raw text from all websites)
outstr (a JSON string)

The system prompt

🟠 System Prompt — tells Claude who it is and what format to use
You are a data extraction assistant for Zap Group, an Israeli digital services company. Your job is to extract structured business information from raw scraped website text. Return ONLY valid JSON — no markdown, no explanation.
💬
"Return ONLY valid JSON" is doing critical work. Without it, Claude would wrap the JSON in a markdown code fence like ```json ... ``` and add friendly text like "Here's what I found!" — which would completely break json.loads() later. The word ONLY forces Claude to output nothing but the JSON object.

The user prompt

🔵 User Prompt — the actual task with the schema and the data
Extract all business information from the following scraped data and return a JSON object with these fields: { "business_name": "Hebrew business name", "business_name_english": "English transliteration", "owner_name": "if found", "phone": "main phone number", "email": "if found", "address": "full address if found", "city": "city name", "region": "region/area", "services": ["list of services offered"], "service_areas": ["list of cities/areas served"], "brands": ["brands they work with"], "years_experience": "number or description", "description": "2-3 sentence Hebrew description", "website_url": "their current website", "social_media": {"platform": "url"}, "google_rating": "if found", "google_reviews_count": "if found", "testimonials": ["key customer quotes"], "unique_selling_points": ["what makes them stand out"], "notes_for_producer": ["observations useful for the Zap producer"] } SCRAPED DATA: {scraped_text}
💬
The blue highlight shows where the actual scraped website text gets injected via the f-string ({scraped_text}). Everything else is literal text — it's the same every time. The JSON schema tells Claude exactly what fields to look for and what to name them, so the output is always the same structure regardless of what's on the website.

The markdown strip

result = call_claude(system, prompt, max_tokens=4096)

if result.startswith("```"):
    result = result.split("\n", 1)[1].rsplit("```", 1)[0]

return result
🧹
What the strip does, step by step:

If Claude returned: ```json\n{"business_name": "יגאל"}\n```

result.split("\n", 1) splits into: ["```json", '{"business_name": "יגאל"}\n```']
[1] takes the second part: '{"business_name": "יגאל"}\n```'
.rsplit("```", 1) splits from the right: ['{"business_name": "יגאל"}\n', '']
[0] takes the first part: '{"business_name": "יגאל"}' — clean JSON.

The 1 in both split calls means "split only once." This protects against cases where the content itself might contain backticks.

💬
Rule 6 is a bug fix baked into the prompt. The original version said "confirm their phone number" — and Claude wrote "פרטי הטלפון: 072-3977065", which reads as if it's Zap's phone number. By explicitly saying "phrase it as questions TO the client" and "their phone number is their number, not ours," Claude now correctly writes "האם המספר שלך הוא 072-3977065?"

DESIGN_SYSTEM_PROMPT  (not a function — a constant)
A long string stored at module level. Used as the system prompt for all 5 website pages. Defined once, referenced by name in generate_draft_website().
📌
Why is this a constant and not written inside the function?
Because it's identical for all 5 page calls. If it were inside generate_draft_website(), Python would recreate the same string 5 times in memory. More importantly, it's long and complex — keeping it at the top of the file makes it easy to find and edit without digging into a function.

The full content of DESIGN_SYSTEM_PROMPT

🟠 System Prompt — used for every website page generation
You are an elite web designer at Zap Group creating a draft website for a new client. You produce distinctive, production-grade HTML that avoids generic "AI slop" aesthetics. DESIGN PRINCIPLES: - Typography: Use Google Fonts — choose distinctive, characterful fonts. NEVER use generic fonts like Arial, Inter, Roboto, or system fonts. Pair a bold display font (e.g., Heebo Black for Hebrew headers) with a refined body font (e.g., Heebo Light/Regular for text). Import via <link> tag from fonts.google.com. - Color: Commit to a cohesive palette using CSS variables. Use a dominant color with sharp accents — not timid, evenly-distributed colors. For an AC/cooling business: deep navy + electric cyan accent + clean whites. Define all colors as CSS custom properties in :root. - Spatial Composition: Generous negative space. Asymmetric hero sections. Grid-breaking elements where they surprise. Avoid cookie-cutter layouts. - Motion: CSS transitions on hover states. Subtle scroll animations via CSS only. One well-orchestrated page load with staggered reveals (animation-delay). - Backgrounds & Depth: Gradient meshes, subtle geometric patterns, layered transparencies, or textured backgrounds. Never flat solid white. - Details: Custom styled buttons, smooth box-shadows with multiple layers, border-radius choices that feel intentional, micro-interactions. CRITICAL RULES: - Every page must be a COMPLETE standalone HTML file with all CSS inline in a <style> tag - RTL direction (dir="rtl" lang="he") — all text in Hebrew - Mobile responsive with proper media queries - Navigation bar linking to: index.html, services.html, about.html, areas.html, contact.html - Footer with business name and phone - Use ACTUAL client data — never placeholder text like "Lorem ipsum" - The design should feel like it was crafted by a human designer, not generated by AI
💬
Why "CRITICAL RULES" in caps? Models pay attention to emphasis. Design principles are suggestions for style. Critical rules are hard constraints — things that will break the output if Claude ignores them. "Standalone HTML with inline CSS" is critical because these files open directly in a browser without a server, so external CSS files wouldn't load. "RTL" is critical because Hebrew text breaks without it.

def _format_images(images):
    if not images:
        return ""
    lines = ["REAL IMAGES FROM CLIENT'S SITE (use these URLs directly in <img> tags):"]
    for i, img in enumerate(images, 1):
        lines.append(f'  {i}. <img src="{img["url"]}" alt="{img["alt"]}">')
    return "\n".join(lines)
if not images: return "" Early exit if no images If collect_images() found nothing, this returns an empty string. The empty string gets injected into the prompt harmlessly — Claude won't see any image instructions and will skip the gallery section.
enumerate(images, 1) Loop with a counter starting at 1 enumerate(list) gives you (index, item) pairs. The second argument 1 starts the counter at 1 instead of 0 — so the output is numbered "1, 2, 3..." not "0, 1, 2..."
f' {i}. <img src="{img["url"]}"...' Building ready-made HTML tags for Claude We give Claude complete <img> tags, not just URLs. This means Claude can paste them directly into HTML without guessing the syntax. The double quotes inside the f-string use single outer quotes to avoid conflict.
"\n".join(lines) Joining a list into a single string lines is a list of strings. "\n".join(lines) combines them with a newline between each — making a multi-line text block Claude can read. This is more readable in the prompt than a single long line.
What Claude receives when images exist:
REAL IMAGES FROM CLIENT'S SITE (use these URLs directly in <img> tags):
1. <img src="https://imazganim.co.il/images/ac1.jpg" alt="מזגן">
2. <img src="https://imazganim.co.il/images/team.jpg" alt="צוות">

def generate_draft_website(client_card_json, images=None):
    pages = {}                                    # will collect all 5 pages here
    images_block = _format_images(images or []) # prepare image text for prompt

    page_specs = {
        "index.html":    "Homepage — dramatic hero section...",
        "services.html": "Services page — showcase all services...",
        "about.html":    "About page — tell the business story...",
        "areas.html":    "Service areas page — geographic coverage...",
        "contact.html":  "Contact page — make it easy to reach out...",
    }

    for filename, description in page_specs.items():
        prompt = f"""Create this page:
{description}
{images_block}
CLIENT DATA:
{client_card_json}"""

        html = call_claude(DESIGN_SYSTEM_PROMPT, prompt, max_tokens=8192)
        if html.startswith("```"):
            html = html.split("\n", 1)[1].rsplit("```", 1)[0]
        pages[filename] = html

    return pages
pages = {} Empty dict to collect results This accumulates {"index.html": html, "services.html": html, ...} as the loop runs. Returned at the end.
images or [] Handling None safely If images is None (not passed in), None or [] evaluates to []. Passing None to _format_images would crash; passing [] returns an empty string safely.
for filename, description in page_specs.items(): Iterating over a dict .items() returns key-value pairs. Each loop gives you the filename ("index.html") and its spec ("Homepage — dramatic hero..."). Python unpacks them directly into two variables.
call_claude(DESIGN_SYSTEM_PROMPT, prompt, max_tokens=8192) Using the shared constant as system prompt Note that DESIGN_SYSTEM_PROMPT (the constant) goes in the system position, and the page-specific prompt goes in the user position. Claude has no memory between calls — the design consistency comes entirely from the same DESIGN_SYSTEM_PROMPT being used in every call.
pages[filename] = html Storing the result in the dict After each API call, we store the HTML under the filename key. By the time the loop finishes, pages contains all 5 pages.

What the user prompt looks like for each page

🔵 User Prompt — example for index.html
Create this page for a business website: Homepage — the most important page. Include: - A dramatic hero section with the business name, a compelling Hebrew tagline, and a large call-to-action button with the phone number - A brief "why choose us" section with 3-4 key selling points as icon-style cards - A testimonial highlight - If real images are provided, use 1-2 of them in the hero or as background REAL IMAGES FROM CLIENT'S SITE (use these URLs directly in <img> tags): 1. <img src="https://imazganim.co.il/images/ac1.jpg" alt="מזגן"> ... Use the client data below for ALL content — real business info only. Output ONLY the complete HTML file, no explanation. CLIENT DATA: {"business_name": "יגאל מזגנים", "phone": "072-3977065", ...}
💬
Three things get injected: the page-specific description (changes each loop), the images block (same for all pages), and the client JSON (same for all pages). The description is what differentiates homepage from services page from about page.
🔢
This function makes 5 API calls total — one per page. Each call costs time and money. We could have asked Claude to generate all 5 pages in one call, but a full 5-page website would exceed 8192 tokens and get cut off. Separate calls also let each page be fully formed and consistent.
